# AI Hallucination Lab

AI 답변에서 사실 주장(Claim)을 추출하고, Tavily 웹 검색 Evidence와 Gemini 판정을 결합해 환각 가능성을 보여주는 반응형 웹 앱입니다.

## 기능

- Gemini 기반 Claim 추출 및 Evidence 비교 판정
- Claim별 Tavily 검색 결과(title, URL, content, score) 표시
- TRUE, FALSE, PARTIALLY TRUE, UNCERTAIN 판정 및 보수적 confidence
- 전체 발견 주장, 검증 주장, 미검증 주장과 검증 범위 표시
- 실제 판정된 주장만 사용한 Hallucination Rate 표시
- 검증 우선순위와 답변 전반의 구간별 표본 선택
- API 키는 서버에서만 읽고 브라우저로 전달하지 않음
- 동일 Claim 검색 결과를 10분간 메모리 캐시
- 동일 입력의 검증 결과를 3분간 메모리 캐시 (최대 100건)

## 실행

Node.js 20.12 이상에서 이 저장소 폴더를 현재 폴더로 두고 실행합니다.

```powershell
npm install
npm start
```

브라우저 주소는 `http://localhost:4173`입니다. 다른 포트는 `$env:PORT=4174`를 설정한 뒤 실행합니다. 4173이 이미 사용 중이면 기존 서버를 재사용하라는 안내를 출력합니다.

## API 키 설정

1. [Google AI Studio](https://aistudio.google.com/app/apikey)에서 Gemini 키를 발급합니다.
2. [Tavily](https://app.tavily.com/)에서 Tavily 키를 발급합니다.
3. `.env.example`을 `.env`로 복사하고 키를 입력합니다.

```powershell
Copy-Item .env.example .env
# .env에 GEMINI_API_KEY와 TAVILY_API_KEY를 입력합니다.
npm start
```

`GEMINI_MODEL` 기본값은 `gemini-3.6-flash`이며 환경변수로 변경할 수 있습니다. 키가 없으면 서버는 충돌하지 않고 화면에 `API 키를 설정해주세요.`를 표시합니다.

## 검증 흐름

입력 답변 → Gemini가 최대 30개까지 안전 상한 내에서 전체 사실 주장을 추출 → 중복 제거 및 우선순위/구간 분포에 따라 검증 예산 8/10/12개 선택 → 선택된 주장만 Claim별 Tavily 검색 → Gemini 한 번으로 전체 판정 → 결과 요약 순서입니다. 정상 요청은 Gemini 호출 2회이며 Claim별 Gemini 호출은 없습니다. 검색하지 않은 주장도 `unverified`로 응답에 남겨 발견 주장 수와 검증 수를 구분합니다. Hallucination Rate는 `FALSE / (TRUE + FALSE + PARTIALLY_TRUE)`로 계산하며 UNCERTAIN과 미검증 주장은 포함하지 않습니다. 동일 입력 결과는 3분, 검색은 10분간 서버 메모리에 임시 캐시되며 디스크에는 저장하지 않습니다. 검색 결과가 없거나 차단 출처만 남으면 해당 Claim은 UNCERTAIN으로 처리합니다.

Tavily 결과에서 Wikipedia, 위키류, 블로그, 카페 및 주요 커뮤니티 도메인과 하위 도메인은 제거합니다. 검색 결과는 출처 우선순위, Tavily 점수, 본문 관련도를 반영해 정렬하고, 판정 요청에는 Claim당 최대 5개를 전달합니다. Claim 검색 결과는 10분 캐시되고 동일 검색 및 동일 검증의 동시 요청은 in-flight 작업을 공유합니다.

## 테스트 입력

- 사실: `대한민국의 수도는 서울이다.`
- 오류: `대한민국의 수도는 부산이다.`

- 최신 정보: `현재 한국의 대통령은 누구인가?`
- 확인 어려움: 출처 없는 개인 경험이나 예측

## 제한사항

- 검색 결과가 모든 주장을 충분히 뒷받침하지 않을 수 있습니다.
- 검색 결과와 판정은 참고용이며, 중요한 정보는 원문 출처를 직접 확인해야 합니다.
- Tavily와 Gemini의 요금, rate limit, 모델 접근 조건은 계정에 따라 달라질 수 있습니다.


## Gemini 호출 수와 무료 API 한도

기존 구현도 정상 요청은 추출 1회 + 전체 주장 일괄 판정 1회였습니다. 그러나 각 단계에 최대 3회의 재시도가 있어 한 번의 검증이 최대 8회까지 호출될 수 있었으며, 재시도를 포함한 공통 RPM 제한이 없었습니다. 기존 버튼 비활성화, 결과 캐시, 동일 입력의 동시 작업 공유는 유지합니다.

수정 후 실제 Gemini 호출 수(재시도 없는 경우):

| 처리 조건 | Gemini 호출 수 |
| --- | ---: |
| 새 입력, 외부 근거 검색 후 전체 주장 일괄 판정 | 2 |
| 추출된 주장이 없거나, 모든 검색에서 유효한 근거가 없음 | 1 |
| 3분 이내 동일 입력의 결과 캐시 재사용 | 0 |
| 동일 입력의 진행 중 작업 공유 | 추가 0 (최초 요청에서 집계) |
| 로컬 일일 예산 소진으로 시작 전 차단 | 0 |

각 Gemini 단계는 최대 2회만 재시도하므로 두 단계 모두 재시도 후 성공할 경우 최대 6회입니다. 재시도도 RPM/RPD 예산에 포함됩니다. 429/실패가 나도 전송 시도는 보수적으로 사용량에 포함합니다. 실제 계정에서 이미 발생한 과거 오류는 서버 로그가 없으면 확정할 수 없습니다.

- `.env`의 `GEMINI_RPM=5`, `GEMINI_RPD=20`은 앱의 기본 예산입니다. **무료 API의 모든 모델에 공통인 공식 한도가 아닙니다.** AI Studio에서 실제 모델/프로젝트의 RPM, RPD, TPM과 사용 가능 여부를 확인해 설정하세요. `GEMINI_MODEL`도 실제 접근 가능한 모델 ID로 설정합니다. 서버가 한도를 자동 조회하거나 TPM을 계산하지는 않습니다.
- 서버 전체가 같은 대기열을 공유하며, 기본 RPM 5에서는 약 12.02초 간격으로 전송합니다. 60초 이동 구간 제한과 전역 429 대기도 적용합니다. 초기화 직후에도 두 Gemini 단계 사이에 대기가 생길 수 있습니다.
- 429는 `Retry-After`(초/HTTP 날짜), Gemini `RetryInfo`와 지수 백오프 + 무작위 지연을 반영합니다. 헤더가 없더라도 최소 60.1초 기다립니다. 5xx에도 제한된 지수 백오프를 적용합니다. 180초를 넘는 재시도 지연은 사용자에게 오류를 반환하며, 대기열의 요청별 대기도 180초로 제한합니다.
- 제공자가 일일 할당량 소진을 명시하면 즉시 재시도를 중단하고 해당 Pacific 날짜의 후속 전송도 차단합니다. 0 할당량 역시 재시도하지 않습니다. 일반 429는 RPM/TPM/공유 프로젝트 사용량 등일 수 있으므로 항상 RPM 문제로 단정하지 않습니다.
- `.runtime/gemini-usage.json`에 시도 횟수, 최근 전송 시각, 대기/일일 차단 상태만 저장합니다. API 키, 입력, 검색 결과는 이 파일에 저장하지 않습니다. 재시작 후에도 카운터를 유지하며 RPD는 America/Los_Angeles 자정에 초기화합니다. 이 파일을 유지할 수 있는 쓰기 가능한 디스크가 필요합니다. Git과 정적 파일 제공에서 제외됩니다.
- 예산은 **단일 서버 프로세스**에서 사용한 값입니다. 같은 프로젝트 키를 다른 앱이나 여러 서버에서도 사용하면 이 서버가 그 사용량을 알 수 없습니다. 이 경우 예산을 낮춰 여유를 두거나 중앙 저장소/공통 제한기를 사용해야 합니다. 기본 RPD 20에서는 재시도 없는 새 입력을 약 10회 검증할 수 있습니다.

각 전송은 서버에 검증 ID, 단계, 실제 누적 호출 수, 재시도 번호, 일일 사용량을 남깁니다. 완료/실패/캐시/공유 요청마다 `[verify-summary]`를 출력합니다. 응답의 `apiUsage`와 브라우저 콘솔 및 화면에도 이 요청이 추가로 발생시킨 호출 수와 재시도 수가 표시됩니다. 공급자 오류 원문은 로그나 브라우저에 전달하지 않습니다.

실제 Tavily 외부 검색, 차단 출처 제거, 출처별 본문 및 URL 표시, 검색 근거에 따른 일괄 판정은 유지됩니다. 근거가 전혀 없는 주장은 UNCERTAIN으로 남깁니다.

## 실시간 검증 로그 모달

상단 오른쪽 **로그 보기**를 누르면 **실시간 검증 로그** 모달이 열립니다. X, ESC 또는 모달 바깥 클릭으로 닫습니다. 모달이 닫혀 있어도 검증과 로그 수신은 계속되며, 다시 열면 현재 페이지의 이전 기록이 유지됩니다. 새 로그는 내부 스크롤의 맨 아래에 추가되며 INFO/SUCCESS/WARNING/ERROR로 구분합니다. **로그 복사**는 현재 기록을 복사하고 **로그 지우기**는 화면 기록만 지우므로 진행 중인 검증에 영향을 주지 않습니다. 페이지를 새로고침하면 화면 기록은 초기화됩니다.

브라우저는 검증 시작 전에 검증별 무작위 ID로 `/api/logs/<id>`에 SSE 연결을 열고, `/api/verify`에 동일한 `logId`를 전달합니다. 로그는 실제 서버 작업 지점에서 발생하며 임의 타이머로 생성하지 않습니다. 연결이 잠시 끊기면 EventSource가 Last-Event-ID로 재연결해 서버의 최근 기록(검증별 최대 500개)을 이어받습니다. 리버스 프록시를 사용한다면 해당 경로의 응답 버퍼링을 끄고 SSE 장기 연결을 허용해야 합니다. 서버 재시작 시 메모리에 있는 스트림 기록은 사라집니다.

서버 로그 이벤트는 고정된 상태 문구와 숫자만 전달합니다. 입력 답변, 주장 원문, 검색 본문/URL, API 키, 인증 헤더, 공급자 오류 원문은 포함하지 않습니다. 스트림은 무작위 ID별로 분리되며 전역 서버 콘솔을 브라우저로 중계하지 않습니다. 기존 결과 화면의 API 호출 로그는 모달로 옮겼으며 결과 판정과 외부 근거 표시는 유지합니다.
